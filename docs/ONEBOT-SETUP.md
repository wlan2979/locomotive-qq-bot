# OneBot 11 接入指南

Locomotive 是**通用 OneBot 11 客户端**：它自己不做 QQ 登录，需要你准备一个兼容 OneBot 11 的协议端，并让协议端开启「正向 WebSocket」服务。

本文只讲通用的 OneBot 11 侧配置与排错，不指定、也不推荐任何具体协议端。具体安装步骤请以你选用的那个协议端的官方文档为准。

## 你需要准备什么

| 项 | 说明 |
| --- | --- |
| 协议端 | 任意实现了 OneBot 11 标准、支持**正向 WebSocket** 的协议端 |
| 已登录的账号 | 协议端里完成登录，状态为在线 |
| WebSocket 地址 | 形如 `ws://127.0.0.1:3001`，端口以你的协议端配置为准 |
| 访问令牌 | 可选。协议端配置了 token 就必须填一致的值 |
| 模型 API Key | 在 Locomotive「模型」页填写，支持 DeepSeek 及任意 OpenAI 兼容接口 |

## 配置步骤

1. **在协议端里开启正向 WebSocket 服务**
   - 找到「网络配置 / 连接配置 / OneBot 配置」一类的设置项
   - 新增一个 **WebSocket 服务端**（注意方向：是协议端监听、客户端连接）
   - 监听地址建议 `127.0.0.1`，端口自定（常见 3001、6700、8080）
   - 消息格式选 **array**（Locomotive 按数组格式解析，字符串格式有兜底但不保证全部特性）
   - 如设置了访问令牌，记下它

2. **确认协议端已登录**
   - 协议端界面或日志里能看到账号在线
   - 如果协议端没登录，WebSocket 端口可能不会监听，或者连上但收不到事件

3. **在 Locomotive 里填写连接**
   - 打开「模型」页，滚到底部的「OneBot 11 连接」
   - 填 WebSocket 地址，例如 `ws://127.0.0.1:3001`
   - 填访问令牌（没设置就留空）
   - 点「保存连接设置」

4. **连接**
   - 回到「机器人」页，点「连接 OneBot」
   - 状态变成「已连接」即可用

5. **验证**
   - 私聊机器人发一句话，应能收到回复
   - 群聊需要 @ 机器人才触发

## 地址格式

| 场景 | 示例 |
| --- | --- |
| 协议端与本软件在同一台机器 | `ws://127.0.0.1:3001` |
| 协议端在另一台机器（同一局域网） | `ws://192.168.1.10:3001` |
| 协议端启用了 TLS | `wss://example.com/onebot` |

只接受 `ws://` 或 `wss://`，不接受 `http://`。地址里不能带用户名密码。

## 常见问题

**连不上 / 一直显示「正在连接 OneBot 服务」**

- 确认协议端进程在运行，且已登录账号
- 确认 WebSocket 是「服务端」模式而不是「客户端」模式（方向反了连不上）
- 用 `netstat -ano | findstr :3001` 确认端口在 LISTENING
- 地址端口是否与协议端配置完全一致
- 防火墙是否拦了本机回环之外的地址

**连上了但发消息没反应**

- 群聊必须 @ 机器人；私聊直接发
- 协议端是否配置了「上报自身消息」（`reportSelfMessage`），开了会导致自己回自己
- 看 `%LOCALAPPDATA%\Locomotive\bot-process.log` 有没有「收到消息」记录

**令牌报错**

- 协议端配置了 token，就必须在 Locomotive 里填一模一样的值
- 改了令牌后要在 Locomotive 里重新保存一次（令牌留空会沿用上次保存的值）

**掉线后不恢复**

- Locomotive 会自动重连（指数退避，最长 60 秒）
- 但协议端如果整个挂了，重连也没用，需要先恢复协议端
- 日志里连续 5 次失败会输出 ERROR 级别提示

## 安全提醒

- WebSocket 服务**只监听 `127.0.0.1`**，不要暴露到公网
- 如果必须跨机器，请走内网 + 令牌，不要直接映射公网端口
- 协议端自身的许可与合规要求由你负责确认，包括是否允许商用
- QQ 账号使用第三方协议端存在风控风险，建议用小号
